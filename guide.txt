FutureMe 後端部署待辦
=======================

0. 修正檔案權限（若曾以 root 部署）
   - `sudo chown -R connie:connie /home/connie/FutureMeMailApp/server`
   - 沒有正確權限會導致 `npm install` 無法寫入 `package-lock.json` 或 `node_modules`。

1. 安裝/驗證 Node 依賴  
   - 進入後端目錄：`cd ~/FutureMeMailApp/server`  
   - 安裝套件：`npm install`（包含 express、mysql2、firebase-admin…）。  
   - 建立環境檔：`cp .env.example .env` 後填入 `PORT`, `DB_*`, `SMTP_*`；`DB_PASS` 必須與資料庫實際密碼一致；`GOOGLE_APPLICATION_CREDENTIALS` 指向 FCM 服務帳戶 JSON 路徑。
   - 在伺服器建立 `~/FutureMeMailApp/server/keys/`，把 Firebase 服務帳戶 JSON 放在此資料夾並 `chmod 600`，.env 指到該路徑。

2. 確認 MariaDB 設定  
   - 以 `sudo mysql` 建立資料庫與使用者（並設定與 `.env` 相同的密碼）：  
     ```
     CREATE DATABASE futureme DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
     CREATE USER 'futureme'@'localhost' IDENTIFIED BY '<strong-password>';
     GRANT ALL PRIVILEGES ON futureme.* TO 'futureme'@'localhost';
     FLUSH PRIVILEGES;
     ```  
   - 建表：  
     ```
     USE futureme;
     CREATE TABLE future_mail (
       id CHAR(36) PRIMARY KEY,
       write_date DATE NOT NULL,
       receive_date DATE NOT NULL,
       subject VARCHAR(255) NOT NULL,
       content TEXT NOT NULL,
       email VARCHAR(255),
       device_token VARCHAR(255),
       device_token VARCHAR(255),
       delivered TINYINT(1) DEFAULT 0,
       delivered_at TIMESTAMP NULL DEFAULT NULL,
       created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
     );
     ```
   - 若已有資料表，可依序執行：
     ```
     ALTER TABLE future_mail ADD COLUMN IF NOT EXISTS device_token VARCHAR(255);
     ALTER TABLE future_mail ADD COLUMN IF NOT EXISTS delivered TINYINT(1) DEFAULT 0;
     ALTER TABLE future_mail ADD COLUMN IF NOT EXISTS delivered_at TIMESTAMP NULL DEFAULT NULL;
     ```

3. 測試 Node API  
   - 啟動服務：`npm run dev` 或 `pm2 start src/index.js --name futureme-api`  
   - 在 VPS 內部測試：  
     ```
     curl -X POST http://127.0.0.1:8080/api/future-mails \
       -H "Content-Type: application/json" \
       --data-binary '{"writeDate":"2025-01-01","receiveDate":"2025-12-31","subject":"test","content":"hello","email":"you@example.com"}'
     ```
     （請保持 JSON 為單行或使用 `--data-binary @payload.json`，避免換行造成 `Bad control character` 錯誤。）
   - 取得信件列表：  
     ```
     curl -s http://127.0.0.1:8080/api/future-mails | jq
     curl -s https://futuremail.cocotoget.com/api/future-mails | jq
     ```
   - 健康檢查：  
     ```
     curl -s http://127.0.0.1:8080/health
     curl -s https://futuremail.cocotoget.com/api/health
     ```
   - Android 端（`WriteActivity`）會自動讀取 FCM token 並附在 `deviceToken`，不需手動輸入；若模擬器尚未登入 Google 服務或無法取得 token，Post API 仍可正常測試，但推播會被略過。
   - Android 專案已整合 Firebase Messaging（下載 `google-services.json`、Gradle 套用 Google services plugin、加入 `firebase-messaging` 依賴）；當 `FirebaseMessaging.getInstance().token` 取得 token 後，會透過 `MainApplication` 暫存，再由 `WriteActivity` 帶出。
   - Android 13+ 需要求 `POST_NOTIFICATIONS` 權限：`MainActivity` 會在啟動時動態請求，若使用者拒絕則不會收到推播（可提醒使用者手動開啟）。

4. 設定 Nginx 反向代理  
   - 需以 sudo 編輯 `/etc/nginx/sites-enabled/futuremail.cocotoget.com`，加入 API 反向代理：  
     ```
     location /api/ {
         proxy_pass http://127.0.0.1:8080/;
         proxy_set_header Host $host;
         proxy_set_header X-Real-IP $remote_addr;
         proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
         proxy_set_header X-Forwarded-Proto $scheme;
     }
     ```  
   - 測試並重新載入：`sudo nginx -t && sudo systemctl reload nginx`。  
   - 從外部測試：`curl https://futuremail.cocotoget.com/api/future-mails ...`

5. 常駐與監控  
   - 啟動：`pm2 start src/index.js --name futureme-api --cwd ~/FutureMeMailApp/server`  
   - 儲存並設定開機自動啟動：`pm2 save` 後執行 `sudo env PATH=$PATH:/usr/bin pm2 startup systemd -u connie --hp /home/connie`  
   - 若需每日推播排程：`pm2 start src/scheduler.js --name futureme-worker --cwd ~/FutureMeMailApp/server`（會在台灣時間每日 09:00 執行，採 data-only FCM 推播，App 端 `FutureMessagingService` 會接收並顯示通知，點擊後開啟 OverviewActivity）  
   - 監控：`pm2 status`、`pm2 logs futureme-api`、`pm2 logs futureme-worker`、`mysql -u futureme -p futureme -e "SELECT COUNT(*) FROM future_mail;"`。
